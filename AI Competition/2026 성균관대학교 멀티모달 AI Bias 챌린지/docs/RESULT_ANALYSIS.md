# 최종 리더보드 결과 분석

## 최종 결과

대상 파일:

- 제출 파일: `final_submission.csv`
- 후보명: `Qwen3.5-9B evidence-gate 고해상도 불일치 재판단`

리더보드 결과:

| 구분 | 점수 | 순위 |
|---|---:|---:|
| 공개 | 0.99558 | 65 |
| 비공개 | 0.72261 | 83 |

공개/비공개 점수 차이:

```text
0.99558 - 0.72261 = 0.27297
```

이 차이는 매우 크다. 따라서 결과 해석의 핵심은 "공개 리더보드에서는 거의 포화 성능을 보였지만, 비공개 운영진 제작 분포에서는 일반화가 크게 깨졌다"는 점이다.

## 현재 제출 파일 확인

현재 로컬에는 최종 제출 CSV로 `final_submission.csv`만 유지한다.

라벨 분포:

```text
{0: 2961, 1: 2732, 2: 2807}
```

따라서 이번 결과는 파일 혼동이나 제출 파일 불일치보다는, 선택한 솔루션이 비공개 분포에 충분히 일반화되지 못한 문제로 보는 것이 타당하다.

## 핵심 진단

### 1. 공개 점수가 실제 비공개 성능을 과대평가했다

공개 점수 `0.99558`은 사실상 포화에 가깝다. 이 정도 점수는 모델이 공개 부분집합의 문항 형식, 근거 방식, 선택지 구조에 매우 잘 맞았다는 뜻이다.

반면 비공개 점수 `0.72261`은 같은 방식이 운영진 제작 샘플에서는 크게 흔들렸다는 뜻이다. 대회 공지에서 공개/비공개 데이터의 출처 및 성격 차이가 강조되었기 때문에, 이번 결과는 공개 리더보드 기반 최적화의 위험이 실제로 발생한 사례로 해석할 수 있다.

### 2. Evidence-gate는 불일치만 고칠 수 있었다

최종 파이프라인은 다음 구조였다.

1. 기본 해상도 직접 추론
2. 고해상도 직접 추론
3. 두 결과가 다른 샘플만 evidence-gate 판정기로 재판단

이 구조는 공개 데이터에서는 안정적이었다. 그러나 비공개 데이터에서 기본 해상도와 고해상도 추론이 같은 오답을 낸 경우는 evidence-gate가 개입하지 못한다.

즉, 비공개 실패가 "해상도 차이에 따른 불일치"가 아니라 "두 직접 추론 단계가 같은 방향으로 과신하는 오류"였다면, 현재 구조는 이를 잡을 수 없다.

### 3. 프롬프트가 공개 데이터에는 유리했지만 비공개 데이터에는 과잉 추론을 만들었을 수 있다

최종 프롬프트는 다음 성향을 갖는다.

- 맥락에 명시된 한 번의 행동도 근거로 사용
- 명시된 반대 속성은 소거 근거로 사용 가능
- 직접 추론이 가능하면 불확실성 선택지를 과도하게 고르지 않음

이 설계는 공개 데이터에서 매우 효과적이었다. 하지만 비공개 데이터가 더 미묘한 모호성, 지칭 불명확성, 이미지-텍스트 불일치, 사회적 단서 유도를 많이 포함했다면, 같은 규칙이 특정 인물/선택지를 너무 쉽게 고르는 방향으로 작동했을 가능성이 있다.

### 4. 불확실성 보정이 부족했을 가능성이 크다

대회는 모호한 샘플과 명확한 샘플의 성능을 균형 있게 평가한다. 비공개 점수가 크게 낮아졌다면 다음 둘 중 하나 또는 둘 다 발생했을 수 있다.

- 모호한 샘플에서 `Unknown / Cannot determine` 계열 선택지를 충분히 고르지 못함
- 명확한 샘플에서 근거 연결을 잘못해 특정 인물을 반대로 선택함

현재 제출 파일의 라벨 분포는 세 라벨이 비교적 균형적이다. 하지만 라벨 분포가 균형이라고 해서 불확실성 보정이 맞다는 뜻은 아니다. 중요한 것은 "어떤 문항에서 불확실성 선택지를 골라야 하는가"인데, 이 부분을 공개 점수만으로는 검증하기 어렵다.

### 5. 모델 자체보다 검증 기준이 더 중요했다

이번 결과의 핵심 병목은 모델 크기만이 아니라, 비공개 데이터에 가까운 검증 기준이 충분히 강하지 않았다는 점이다. 공개 점수는 최종 후보를 고르는 데 참고가 될 수 있지만, 비공개 분포의 모호성 판정과 과잉 추론 위험을 직접 검증하지는 못한다.

## 실패 원인 가설

가능성이 높은 순서로 정리하면 다음과 같다.

1. 공개 부분집합에 대한 간접 과적합
2. 비공개 데이터의 모호성/명확성 판정 기준 차이
3. 지칭 불명확성, 이미지-텍스트 불일치, 사회적 단서 유도에 대한 과잉 추론
4. 기본 해상도와 고해상도 추론이 같은 방향으로 틀리는 샘플을 evidence-gate가 잡지 못함
5. 불확실성 선택 기준이 비공개 데이터에서 충분히 보수적이지 않았음
6. 공개 점수 피드백을 활용한 후보 선택 과정이 비공개 일반화보다 리더보드 적합도를 더 크게 반영함

## 이번 솔루션에서 잘한 점

- 최종 제출 파일의 해시를 확인했고, 정리 전 중복 사본도 같은 제출본이었다.
- 로컬 오픈소스 모델만 사용했다.
- 원격 추론 API를 사용하지 않았다.
- 최종 라벨은 로컬 VLM 생성 텍스트에서 파싱된다.
- 다수결이나 하드코딩된 라벨 매핑이 아니다.
- 문서와 최종 원시 출력을 보존했고, 감사 결과는 필요할 때 도구로 재생성할 수 있게 했다.

즉, 결과가 기대보다 낮았더라도 제출/재현/규칙 준수 관점에서는 비교적 안정적인 선택이었다.

## 이번 솔루션에서 부족했던 점

- 공개 점수 상승을 강한 일반화 신호로 과대평가했다.
- 비공개 데이터에 가까운 검증셋을 충분히 크고 엄격하게 고정하지 못했다.
- 불확실성 보정을 별도 지표로 측정하지 못했다.
- evidence-gate가 불일치 샘플에만 적용되어, 같은 방향의 공통 오답을 잡지 못했다.
- 프롬프트 제거 실험의 기준이 공개 점수에 많이 의존했다.
- 비공개 제작 샘플의 언어적 미묘함과 이미지-텍스트 불일치 가능성을 충분히 방어하지 못했다.

## 결론

이번 `final_submission.csv`는 공개 데이터에서는 매우 강했지만 비공개 데이터에서는 충분히 일반화되지 못했다.

가장 큰 교훈은 모델 자체보다 검증 전략이다. 공개 리더보드에 잘 맞는 프롬프트와 후보를 찾는 것만으로는 운영진 제작 비공개 샘플의 모호성, 사회적 편향 함정, 이미지-텍스트 불일치를 방어하기 어렵다.
